# RealtimeP2PKit

This folder contains the reusable runtime and Editor window. `Assets/Example` is a separate consumer. To use the library in another Unity 6 project, copy this folder and `Assets/Packages` (MessagePack and NativeWebSocket DLLs with `.meta` files), then add Unity.WebRTC 3.0.0, Newtonsoft.Json 3.2.2, Burst 1.8.27, and Collections 2.6.2 to the target project's `Packages/manifest.json`.

Open **RealtimeP2PKit > Connection Settings** and choose Local or Remote from **Environment to edit**. Configure that environment's signaling WebSocket base URL and ordered STUN URL list. The window saves `Resources/P2PConnectionSettings.asset`, so the selected Player environment is available in builds. The Editor environment is stored separately in Editor PlayerPrefs.

Call `P2PManager.Instance.Initialize()` and register packet handlers. `P2PConfig` is optional: omitted or null config uses the `gameplay` data-channel label, unreliable delivery with no retransmits, and `Info` logging. To customize these values, create a `P2PConfig` asset and pass it to `Initialize(config)`. After your application reserves membership through HTTP, call `await P2PManager.Instance.ConnectToRoomAsync(playerId, roomId, token, optionalWebSocketBaseUrl)`. This completes when the server acknowledges membership, even if the player is alone. `RoomJoined` reports this acknowledgement; `PeerConnected` fires for each open data channel. `PeerLeft` reports an individual departure, while `ConnectionClosed` reports loss of the local room session. Call `Disconnect()` during teardown and use your HTTP membership API to release the reservation. Matchmaking and HTTP code live in `Assets/Example/Matchmaking` and are not part of this library.

The manager maintains one WebRTC connection per remote participant without a fixed participant limit. `Send(packetId, value)` broadcasts to all open peers; `SendTo(peerId, packetId, value)` targets one peer. Register a sender-aware handler with `RegisterPacketHandler<T>(packetId, (senderId, value) => ...)` to distinguish participants without trusting a sender field inside a packet. The original one-argument packet handler is also supported. `PeerConnectionFailed` reports a failed individual P2P link without closing the other links. DataChannel labels are local to each peer connection and can safely be reused.

Signaling envelopes include `from` and `to`. The server assigns the offerer role explicitly when a participant arrives and derives `from` from the authenticated socket. No offerer/host role is encoded in IDs. The new signaling protocol replaces the original two-peer protocol, so server and clients must upgrade together. Example room capacity is independent of the library: 0 means unlimited. A full mesh uses n−1 connections per client and n(n−1)/2 connections overall; practical capacity depends on hardware and bandwidth.

The signaling server must implement `/parties/room/{roomId}` as in the included `server` project. The STUN-only transport cannot connect every pair of NATs; a TURN relay is required for those cases.
